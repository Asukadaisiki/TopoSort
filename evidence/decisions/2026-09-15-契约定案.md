## 1. 输入格式（`.in` / 手工输入共用）

- 每行一条关系 `<a,b>`；宽容变体：空白行跳过、全角 `（）`、`，`、缺尖括号 `a,b`
- 重复边去重；**自环 `<a,a>` 非法**（ParseError）
- 非法行：`ParseError(lineno, line, reason)`，lineno 从 1 计
- 编码 UTF-8（跨平台红线）

## 2. 测试数据文件（`evidence/test-data/`）

- `NNN-描述.in`：输入文本
- `NNN-描述.expected`：JSON。字段：`orders`（全部合法序的列表；截断场景给 `orders_capped` + `count`）、`cycle_nodes`（环用例）、`parse_error_lineno`（坏输入用例）
- 测试代码只读这批文件，**不内嵌图数据**（conftest 的标准图常量除外，属共享基准）

## 3. 事件协议（`app/events/protocol.py` 为唯一权威）

| 事件 | 字段 | 语义 |
|---|---|---|
| Enqueue | node, branch_id | 节点进入某分支候选池 |
| Consume | node, branch_id | 分支消费节点（从图中移除） |
| Fork | branch_id, new_branch_id, node | 分歧点：原分支选 node，新分支待选其他 |
| Complete | branch_id, order: tuple | 该分支得到一条完整拓扑序 |
| DeadEnd | branch_id, stuck_nodes | 分支死路（理论上有环才发生） |
| CycleFound | stuck_nodes | 全局环检测命中 |

- **确定性契约**：同输入 → 事件序列逐项相等；`order` 用 tuple（可哈希、可比）
- branch_id 从 0 开始，Fork 产生递增新 id

## 4. 伪并发时间线（Timeline）

- 每拍（tick）：**按 branch_id 升序交错推进每个活跃分支各一步**，返回本拍事件列表
- `lane_limit`（默认 8）：可视化泳道上限；溢出分支不产生可视化事件但仍计数（Complete 照常）
- 状态机：`running → paused → running → ... → finished`（全部分支终止后 finished）
- `tick_ms`（默认 400）为默认拍间隔；UI 滑块改 `set_speed`

## 5. 渲染层契约（scene）

- 只消费 `layers: dict[str,int]` 与 `StepEvent`，**禁止 import app.models 的算法函数**
- 节点视觉状态机：`idle → ready（Enqueue）→ active（本拍被选中）→ ghost（Consume）`；`stuck`（CycleFound/DeadEnd 的 stuck_nodes）
- 动画时长常量集中在 `Effects`，上界 1000ms

## 6. UI 层契约

- MainWindow 必须是 QWidget（qtbot 兼容）；错误呈现含两类：解析错误（含行号）、发现环
- 结果列表每条 = 一行空格分隔的完整拓扑序

## 7. 跨平台红线（CI 机械检查）

- 路径 `pathlib`；读写显式 `encoding='utf-8'`；写文件 `newline=''`
- `import app.models` / `import app.events` 后 sys.modules 无 PySide6/PyQt

## 8. 标准基准图（conftest 共享）

`<A,C> <A,E> <B,C> <C,D>` → 恰 6 条合法序（清单见 `app/tests/conftest.py`）

## 9. CI 两层判定策略

- **L1 infra**：`test_contracts.py`（零 Qt、pathlib 等机械红线）+ check_docs —— 全平台必须绿，**分支保护强制**（不绿禁止合并）
- **L2 模块**：test_models / test_events / test_scene / test_ui 四个独立 job，`continue-on-error`
  - 含义：红 = 该模块未完成（路标，不是事故）；对应模块 PR 合并时**必须翻绿**（review 人工核对）
  - 好处：任何人的 PR 不会被别人的未完成模块挡住；模块完成进度在 CI 面板一目了然
